# 贴纸系统彻底重构 — 任务需求

> 任务类型：代码重构 + 文档同步
> 提交方式：作为 RFC-001 Flow 的 `requirement` 输入，由 Planner → TextProcessor → Coder → Reviewer → Document_Admin 执行
> 适用版本：v1.26.0-wip 及之后

---

## 一、任务背景

贴纸系统经过多轮增量修补（v1.18 ~ v1.26），目前已形成“文章编辑器贴纸 + 全屏贴纸编辑器 + 文章阅读页贴纸 + 贴纸库”多套相互纠缠的实现：

- 标记解析、渲染、保存逻辑在 `article-editor-mode.js`、`sticker-editor-mode.js`、`detail.js`、`sticker-renderer.js` 等文件中重复或半重复存在；
- `_stickerData` 与 DOM 形成双数据源，拖拽后内存数据不同步，保存时依赖从 DOM 读取，容易引发中间逻辑误用；
- 阅读页与编辑器的浮动渲染显示长期不一致（即 roadmap 中“贴纸浮动渲染显示功能尚未修复”的 WIP 项）；
- 既有审计文档记录了 P0/P1/P2 问题，部分已修复、部分仍是遗留（草稿恢复解析、防重复提交、监听器显式解绑、硬编码默认值等）。

本次任务是对贴纸系统进行**彻底重构**，使其成为职责清晰、单一数据源、阅读/编辑所见即所得、可测试、可维护的独立模块。

## 二、重构目标

1. 贴纸系统的数据模型、标记格式、解析/渲染/序列化逻辑收敛到单一模块，消除跨文件重复实现。
2. 文章编辑器、全屏贴纸编辑器与阅读页共用同一套渲染核心，保证所见即所得。
3. 修复长期遗留的浮动渲染显示问题：贴纸在编辑态与阅读态的位置、尺寸、浮动方向、绕排效果一致。
4. 保持既有文章与草稿数据完全兼容，任何迁移路径都不允许数据丢失。
5. 重构后通过现有测试，并补充必要的单元测试，同步更新相关文档。

## 三、必须满足的要求

### 3.1 数据与兼容性

- 贴纸占位标记继续使用 HTML 注释形式（`<!-- sticker:... -->`）。
- 标记解析必须兼容旧格式（`align=left w=120 h=120`，无 x/y）、当前新格式（`x=... y=... w=... h=... align=...`）以及字段顺序无关的任意组合；未来新增字段不得破坏既有标记。
- 贴纸数据以 `article.stickers`（或等价单一数据源）为权威来源，标记序列化必须与该数据源一致；禁止保存路径产生双份、丢失或顺序错乱。
- 旧文章、旧草稿、旧标记在重构后必须可读、可渲染、可继续编辑，并提供明确的迁移/兼容层说明。

### 3.2 架构与代码质量

- 单一职责：渲染器、解析器、数据模型、编辑器交互、阅读页挂载各自独立模块，禁止跨文件复制粘贴逻辑。
- 单一数据源：贴纸状态（位置/尺寸/对齐/形状等）在编辑、保存、恢复全流程中只有一个权威来源，DOM 仅作为视图，不再作为数据中间层。
- 统一标记读写：所有 create / parse / strip 操作必须经过统一模块导出，业务文件不得保留内联正则副本。
- 遵循项目规范：ES Module、对象字面量或类、2 空格缩进、JSDoc 注释、UI 文案统一在 `js/utils/ui-strings.js`、事件常量统一在 `js/core/event-constants.js`、颜色使用 CSS 变量适配三套主题。
- 不得引入新的运行时框架或重依赖；如确需新增依赖，必须说明理由、体积与替代方案。

### 3.3 交互与渲染

- 阅读页与编辑器（含全屏贴纸编辑模式）的贴纸浮动渲染显示一致：浮动方向、尺寸、文字间距、形状绕排均一致。
- 保留既有交互能力：拖拽移动、缩放、右键菜单（切换对齐/删除）、贴纸库放置、未放置贴纸管理。
- 全屏贴纸编辑模式与文章编辑模式必须共用同一套贴纸状态管理与渲染核心，不得各写一份。
- 移动端（≤768px）维持既有行为：编辑功能禁用、阅读页贴纸缩放适配。
- 三套主题（dark / light / lofi）下贴纸与编辑界面视觉一致。

### 3.4 健壮性与体验

- 修复已记录的关键遗留问题：草稿恢复后贴纸从 content 重新解析、保存/发布防重复、拖拽结束后状态同步、监听器与定时器显式清理、DOM 引用置空。
- 贴纸库加载失败、图片加载失败等异常必须有明确降级与用户提示，不得静默失败。
- 大量贴纸（≥50）时编辑器与阅读页保持流畅，不得出现明显卡顿或内存泄漏。

## 四、验收标准

1. 所有既有贴纸数据（新旧标记、含 `stickers` 字段/仅 content 标记）在阅读页与编辑器中正确渲染，无数据丢失。
2. 编辑态与阅读态贴纸显示一致，长期 WIP 的“贴纸浮动渲染显示”问题关闭。
3. 全仓库不存在重复的贴纸正则、解析或渲染实现；标记读写全部走统一模块。
4. 拖拽/缩放/对齐切换/删除后保存并刷新，位置与属性完整恢复。
5. 草稿保存 → 恢复 → 编辑 → 发布全链路贴纸保持一致。
6. `npm run test`、`npm run build` 通过；新增或更新贴纸相关单元测试（Vitest），覆盖解析、序列化、状态同步与新旧兼容。
7. 更新 `my_first_crew/knowledge/docs/development/sticker-editor.md`、`module-index.md`、`roadmap.md`（若浮动渲染显示确实修复，则标记该 WIP 为已完成），并按 `version-manage.md` 规范同步版本号与更新日志。
8. 交付物包含：重构方案说明（架构/文件清单/迁移策略）、完整代码或补丁、测试与验证结果、文档更新清单。

## 五、明确不做（非目标）

- 不引入 Vue/React 等前端框架，不改变项目整体技术栈。
- 不改变贴纸上传、存储、贴纸库的现有后端接口，除非重构确实需要且能证明收益。
- 不改变文章编辑器与阅读页的其他功能（标题、目录、水印、主题等）。
- 不实现贴纸图层、组合、动画、多选等新功能；本次只做重构与既有功能稳定化。
