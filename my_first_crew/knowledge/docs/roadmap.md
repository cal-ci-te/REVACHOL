# REVACHOL 路线图

> 版本：v1.19.0-wip | 更新：2026-08-19

---

## 项目定位

REVACHOL 是一个面向个人创作者的、可扩展的创作存档与交互工具。  
核心目标：

1. 提供一个不依赖社交反馈的创作空间。
2. 允许用户通过配置（而非代码）扩展交互组件。
3. 保持轻量、可定制、文档驱动。
4. 隐藏深度叙事层，供有探索意愿的用户发现。

> 本项目首先是个人工具，开源是顺便的。功能方向以我自己的使用需求为准，不优先响应外部功能请求。

---

## 当前限制

| 项 | 说明 |
|----|------|
| 无前端路由 | 单页应用，无 URL 状态持久化（页面刷新后状态丢失） |
| 无 HTTPS | 本地开发 + Docker 映射均为 HTTP |
| Vite dev server 部署 | 非生产级静态文件服务，无 gzip/缓存 |
| 测试覆盖不完整 | 仅 core/services/utils 有单元测试，UI 交互无覆盖 |
| 并发能力有限 | SQLite + 单 Node 实例，适合低并发场景 |
| 贴纸存储 | 本地文件系统，受磁盘空间和文件数限制 |

## 长期计划

### 适配器版本（轻量 ↔ 重型切换）

用户可通过环境变量切换底层实现，业务代码无需改动：

| 适配器 | 轻量版（默认） | 重型版（可选） |
|--------|---------------|----------------|
| 数据库 | sql.js (WASM SQLite) | PostgreSQL / MySQL |
| 缓存 | 内存 Map | Redis |
| 消息 | 内存广播 | Redis Pub/Sub |
| 存储 | 本地文件系统 | S3 兼容存储（已实现） |

## 明确不做的方向

- 不提供社交功能（点赞、评论、关注、排行榜）
- 不以“用户增长”为目标
- 不提供云端托管服务
- 不承诺功能请求响应周期
- 不开放商业化授权（当前阶段）

---

## 设计原则（优先级排序）

1. **自己先用**：所有功能必须先满足我自己的需求。
2. **配置驱动**：能用配置解决的问题，不写硬编码。
3. **文档优先**：能用文档说清楚的事，不做额外 UI。
4. **可扩展**：新组件可以独立接入，不影响已有系统。
5. **边界清晰**：明确什么做、什么不做，不被外部需求带偏。
6. **适配器模式**：关键层保持可替换性，轻量版默认，重型版可选。

## 版本规划原则

本项目不按固定周期发布版本。版本号变更依据实际完成的功能集合决定，遵循语义化版本规范：

- **主版本号（MAJOR）**：架构性变更，或与旧版本不兼容的改动。
- **次版本号（MINOR）**：新增功能，且保持向后兼容。
- **补丁版本号（PATCH）**：Bug 修复、性能优化、文档补充，不改变功能行为。

版本发布不设时间表，随功能积累自然推进。
